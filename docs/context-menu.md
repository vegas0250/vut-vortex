# Context Menu Layer

Vortex рисует своё меню. Система только отвечает, какие команды есть у выбранного объекта, и выполняет выбранную команду.

```text
VUT-Vortex
      │
ContextMenuService
      │
┌─────┴──────┐
Windows      Linux
      │            │
Classic      GIO / desktop files
+ отчёт      KDE service menus
modern API   capability detection
      │            │
      └─────┬──────┘
            │
     ContextMenuItem
            │
       vui-menu
            │
     текущая тема VUI
```

Собственные команды Vortex и системные команды проходят через один сервис и одну модель. Экран рисует один `vui-menu` и оставляет в нём только системные пункты.

## Модель

`src/shared/context-menu.ts`

```ts
type ContextMenuTarget =
  | { type: 'file'; paths: string[] }
  | { type: 'folder'; paths: string[] }
  | { type: 'mixed'; paths: string[] }
  | { type: 'background'; directory: string }

interface ContextMenuItem {
  id: string
  label: string
  icon?: string
  enabled?: boolean
  checked?: boolean
  separator?: boolean
  shortcut?: string
  children?: ContextMenuItem[]
  source: 'vortex' | 'windows-shell' | 'linux-system' | 'extension'
  command?: string
}
```

`file` — один или несколько файлов. Одна папка — `folder`. Файлы вместе с папками и несколько папок — `mixed`. Пустое место каталога — `background`.

`source` нужен для диагностики. Вид меню по нему не ветвится.

`icon` — имя иконки VUI. Путь, handle и data URL сюда не попадают: если системной иконки в этом виде нет, поля нет.

## ContextMenuService

`src/main/context-menu/service.ts`

```text
get(query)      модель меню
execute(session, commandId)
dismiss()       отпустить текущую системную сессию
```

Сервис не импортирует API Windows или Linux. Провайдер подставляется в `src/main/context-menu/index.ts`: Windows, Linux или пустой провайдер. Пустой провайдер — место для macOS: UI менять не нужно.

Команды Vortex собирает `vortexItems`. Системные добавляет провайдер. `composeMenu` ставит команды приложения, затем системные, затем «Свойства». Экран рисует только системные пункты: `systemMenuItems` отбрасывает `source: vortex`. Пока список не получен, в меню один отключённый пункт «Загрузка…».

Если провайдер бросает ошибку, сервис отдаёт команды Vortex и не кэширует сбой. Экран эти пункты не показывает: остаётся «Нет системных команд». Ошибка пишется в лог. Приложение не падает. Следующий щелчок пробует систему снова.

## IPC

```text
contextMenu.get({ target, folders, directory, extended, classic, kind, flags })
contextMenu.execute({ session, commandId })
contextMenu.dismiss()
```

Через IPC идут только строки. Индексы shell, PIDL и argv остаются в main. `execute` принимает `sys:` + session, выданный последним `get` для этого выбора. `vortex:*` main не выполняет. Произвольная строка shell отклоняется. `shell:classic` в `execute` не отправляется: экран повторяет `get` для того же выбора и той же точки с `classic: true`.

## Выполнение

Команда выполняется тем механизмом, который её породил.

- Vortex: открыть, новая вкладка, копировать, вырезать, вставить, переименовать, удалить, создать папку, свойства. Текст пункта не разбирается.
- Windows: `IContextMenu.InvokeCommand` у той сессии, которая построила меню. Для глагола `properties` лист открывает `ShellExecuteEx` по идентификатору объекта Shell, в том числе у папки. Путь строкой не передаётся: иначе система показывает «нет приложения, сопоставленного с этим файлом». Владелец листа — окно приложения. Поток помощника на это время присоединяется к его вводу, а вызов не возвращается, пока лист открыт.
- Linux: `spawn(file, args)` без оболочки. Аргументы взяты из desktop-файла, прочитанного провайдером, а не из renderer.

## Windows

Классическое меню: долгоживущий `ShellMenu.exe` (`src/main/platform/shell-menu.cs`). Процесс поднимается при старте и живёт, пока живо приложение. На каждый правый щелчок новый процесс не создаётся.

Процесс ходит в документированный Shell:

- `SHParseDisplayName`, `SHBindToParent`, `IShellFolder`
- `GetUIObjectOf` / `CreateViewObject` для `IContextMenu`
- `IContextMenu2`, `IContextMenu3`
- `QueryContextMenu`, `InvokeCommand`
- `CMF_EXTENDEDVERBS`, если зажат Shift

Так подхватываются расширения, которые зарегистрировались в Shell: архиваторы, Git, облако, антивирус. Их список в коде не зашит.

### Windows 11, современное меню

Короткое меню включается, если сборка не ниже 22000 и в реестре нет ключа классического меню `HKCU\Software\Classes\CLSID\{86ca1aa0-34aa-4e8b-a509-50c905bae2a2}`. Иначе сразу отдаётся полный `IContextMenu`. Shift (`extended`) тоже пропускает фильтр.

Короткий список оставляет глаголы open, openas, openwith, cut, copy, paste, rename, delete, properties, share, windows.share, pintohome, pintostartscreen и вложенные меню. Вырезать, копировать, вставить, переименовать, поделиться и удалить стоят нижней полосой иконок, как в меню Windows 11, а не отдельными строками. У строк свои SVG-иконки по глаголу. В конец списка добавляется «Дополнительные параметры». Это не команда `sys:` и не `InvokeCommand`. Клик повторяет `get` с `classic: true` в той же точке и рисует полный список, включая расширения.

Состав компактного меню Explorer и `IExplorerCommand` снаружи недоступны. Фильтр — приближение по глаголам, не копия Explorer. Не используются недокументированные структуры, внедрение в процесс Explorer и разбор подписи пункта.

## Linux

`LinuxContextMenuProvider` не привязан к Nautilus, Dolphin или Thunar.

Возможности определяются по окружению:

| Среда | Что читается |
| --- | --- |
| Любая freedesktop | desktop-файлы приложений, `shared-mime-info`, `xdg-open` |
| KDE | service menus: `kio/servicemenus`, `kservices5/ServiceMenus`, `kservices6/ServiceMenus` |
| GNOME | те же desktop-файлы. Расширения Nautilus не читаются |
| XFCE | те же desktop-файлы. Thunar не требуется |

`XDG_CURRENT_DESKTOP` ограничивает `OnlyShowIn` и `NotShowIn`.

Расширения Nautilus загружаются внутри Nautilus и не имеют API для другого менеджера. Это записано в capability: `nautilusExtensions: false`.

`Exec` разбирается по desktop entry spec. Коды `%f`, `%F`, `%u`, `%U` подставляются аргументами. Неизвестный код отклоняется. Оболочка (`sh -c`) не запускается.

Индекс desktop-файлов держится в памяти и обновляется не чаще раза в минуту. На щелчок процесс для чтения меню не стартует. Процесс появляется только когда пользователь выполняет команду.

## Кэш

Ключ: ОС, окружение рабочего стола, вид выбора, число объектов, расширения, каталог, сами пути, Shift, признак полного классического меню.

Меню одного файла не отдаётся на несколько файлов. Меню `.txt` не отдаётся на `.jpg`.

Успешный ответ живёт 15 секунд. После `execute` запись сбрасывается: расширение могло изменить набор команд. Windows держит одну shell-сессию, новое выделение её заменяет, старые `commandId` перестают действовать.

Пока выделение не меняется, renderer может показать уже полученные системные пункты без нового IPC. Параллельно смена выделения прогревает меню через 150 мс. Правый щелчок сразу рисует «Загрузка…», либо системные пункты из кэша, и подменяет меню, когда список готов.

## Закрытие и позиция

Закрытие делает `vui-menu` вместе с overlay VUI и контроллер Vortex:

- указатель снаружи и Escape — overlay;
- другое меню, в том числе повторный правый щелчок — контроллер закрывает предыдущее;
- смена выделения, каталога и вкладки — контроллер.

Координаты курсора передаются в `showAt` как есть. `placeLayer` удерживает меню целиком внутри окна: если снизу или сбоку места нет, меню открывается в другую сторону, а слишком длинный список прокручивается внутри себя. После подмены пунктов меню остаётся открытым: `placeLayer` только сдвигает его, без повторного `showAt`, чтобы щелчок по нижней команде, включая «Свойства», не сбрасывался. Наведение на пункт с подменю открывает его сразу. Координаты CSS уже учитывают DPI. Меню — слой внутри окна, поэтому край экрана для него совпадает с краем окна, в том числе на нескольких мониторах, в полноэкранном режиме и рядом с панелью системы.

## Тема и иконки

Цвета, шрифт, отступы, радиус, тень, hover, disabled, разделители, подменю и фокус берутся из токенов VUI. Отдельной темы Windows или Linux нет. Смена темы меняет меню вместе с остальным окном.

Системные bitmap и `HBITMAP` в renderer не передаются. У классического пункта часто нет своей картинки, либо её рисует сам Shell. Поле `icon` остаётся пустым, случайная иконка не подставляется. Команды Vortex используют имена из реестра VUI (`file`, `copy`, `trash-2` и другие).

## Производительность

В разработке и при `VORTEX_CONTEXT_MENU_TRACE=1` пишется:

```text
context-menu requested
context-menu provider started
context-menu system menu obtained
context-menu normalized
context-menu rendered
context-menu total duration
```

В собранном приложении этих строк нет, пока переменная не включена. `VORTEX_CONTEXT_MENU_TRACE=0` выключает их и в разработке. В ответ IPC входят длительности, это несколько чисел.

Первый вызов после старта включает прогрев помощника Windows или индекса Linux. Следующий вызов по тому же выделению берётся из кэша.

## Безопасность

Renderer не получает указатели. Выполнить можно только `commandId`, который сервис выдал для живой сессии и этого выбора. Команда Vortex в native-слое не запускается. Desktop `Exec` не проходит через shell.

## Запасной путь

Нет компилятора Windows, пустой каталог desktop-файлов, ошибка Shell или ещё не написанный провайдер macOS: системный список пуст. Экран показывает «Нет системных команд». Команды приложения остаются на панели.

## Тесты

Автоматические:

- выбор: файл, папка, несколько файлов, смесь, пустое место;
- ключ кэша;
- команды Vortex и общий порядок меню;
- отказ провайдера;
- кэш, чужая сессия, замена выделения на Windows;
- подменю Shell без индекса команды в модели для экрана;
- отчёт по современному меню Windows 11;
- desktop-файлы, service menus, mime, `Exec`, capability;
- IPC не принимает произвольную команду;
- открытие, закрытие, Escape, щелчок снаружи, повторное открытие, подменю, клавиатура, disabled, тема, край окна.

Ручная матрица, когда машина это позволяет:

| | Windows 10/11 | GNOME | KDE | XFCE или другое freedesktop |
| --- | --- | --- | --- | --- |
| Один файл | классические пункты Shell | «Открыть с помощью» | service menu, если установлен | desktop-файлы |
| Папка | меню объекта | пункты для `inode/directory` | пункты для каталога | то же |
| Несколько файлов | меню выделения | только команды с `%F`/`%U` | то же | то же |
| Смесь | меню выделения | команды `all/all` | то же | то же |
| Пустое место | меню фона каталога | команды каталога | service menu каталога | то же |
| Shift+щелчок | расширенные глаголы | — | — | — |
| Расширение | 7-Zip, Git или другое, если установлено | — | пункт из ServiceMenus | — |
| Современное меню Win11 | отдельных пунктов сверх классического меню нет, это ограничение API | — | — | — |

На машине без этого окружения capability-тест проверяет ветку, а ручная строка остаётся непройденной.
